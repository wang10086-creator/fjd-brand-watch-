# 线索复核四阶段交付说明

本次调整限于线索复核及其直接依赖的统计、存储、导出、同步与归档适配。
检索规则、平台与品牌配置、原有自动优先级算法、定时计划保持原有行为。

## 流程

| 当前阶段 | 人工操作 | 结果 |
|---|---|---|
| 待IP对接人初核 | 疑似侵权，并填写依据 | 待IP部门复核 |
| 待IP对接人初核 | 可以排除，填写原因和依据 | 已结案／排除侵权嫌疑 |
| 待IP对接人初核 | 信息不足，记录待补信息 | 留在初核 |
| 待IP部门复核 | 疑似侵权，并指定业务或法务节点 | 待后续处置 |
| 待IP部门复核 | 可以排除，填写原因和依据 | 已结案／排除侵权嫌疑 |
| 待后续处置 | 调整业务／法务节点并记录依据 | 留在后续处置 |
| 待后续处置 | 完成排除判断 | 已结案／排除侵权嫌疑 |
| 待后续处置 | 确认处置已实际完成，记录措施与完成依据 | 已结案／处置完成 |
| 已结案 | 填写重新打开原因 | 新一轮待IP对接人初核 |

补充处理信息中的访问状态、图片判断、证据、持续复查和备注随“确认处理”一并保存。已移除独立暂存入口；历史暂存数据及旧接口继续兼容。

排除原因：授权已核实、正常使用或引用、无关线索或误报、其他排除原因（必填说明）。
处置完成的原因固定为“处置已完成”，措施可多选：停止使用、整改、业务协调、法务办结、其他（必填说明）。
单纯转交部门、沟通中、原页打不开或检索零命中均不自动结案。

## 数据和历史

新增 `reviewWorkflow.version=1`，包括 stage/opinion/node/closure/round/rounds/updatedAt。
每轮保留操作事件及时间、依据、结案信息；第一轮保存原始人工字段。
重新打开增加轮次并清空当前处理节点与当前结案信息，旧轮次保持完整。

旧数据只读映射，不批量覆盖 reviewOutcome/status/decision/confirmedIssue/note/reviewedAt：

| 旧结论 | 新阶段 |
|---|---|
| 待核查 | 初核 |
| 信息不足 | 初核，意见为信息不足 |
| 授权已核实、正常引用、无关／误报 | 已结案，按原原因对应 |
| 具体异常／提交法务 | 待后续处置／法务 |
| 旧 cleared 且无细分结论 | 已结案，明确标注历史类型未注明 |

未知字段保留原值；无法解析的未来流程结构在首次人工操作时保存为原始结构，不伪造核查过程。
旧接口继续接受旧字段，新人工操作同时生成兼容投影。自动检索不会推进或重新打开阶段。

列表四阶段互斥，结案率＝已结案／当前基础筛选范围总数。
业务和法务的二级数量属于待后续处置，不重复加入总数。
日报仍统计当日新增或变化线索，其他存量线索的核查变更保留在当日更新链。
2026-10-20 起（或已有新流程事件的日期）采用统计口径 v2，只计 closed 为结案；
更早日报和已保存快照保留当时口径，历史更新事件及校验内容不覆盖。

本机完整记录使用原 IndexedDB/备份；加密云端传输保留全部轮次和依据。
匿名公共台账仅发布流程元数据，不发布内部依据、其他原因说明、重新打开原因和原始私有备注。

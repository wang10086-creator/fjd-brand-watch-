## 自动 URL 核查

`cloud/url-check.mjs` 只读原始 URL，不递归、不登录、不执行第三方脚本。HTTP/HTTPS 公开地址经 DNS 全量结果校验，socket lookup 固定到已验证地址，阻断内网/元数据、凭据、非标准端口、危险协议及 DNS 重绑定。每次跳转均重新校验地址与 robots；HTTPS 升级、www 规范化、已知跟踪参数清除不算实质迁移。支持有界 HTTP 和正常 meta/Refresh 跳转，不执行 JS 跳转。遵守 robots、noarchive；无可核实内容时保留限制原因。

默认单页最多9秒、正文响应最多1.2MB、保存正文片段最多12000字；每批最多8条、24次实际HTTP请求、总计30秒（独立补查40秒），同主机至少间隔30秒并持久保留冷却。正常页面3天复查、持续复查1天，变化/跳转/下架12小时；无法访问从30分钟指数退避到24小时。新线索与尚未检测线索优先，重复命中中的有效索引变化可请求复查，但不直接变成已核实的页面变化。预算耗尽只进入续查，不伪造访问失败。

正常必须实际取得目标内容。已变更只比较两次真实原网页证据，优先复用已有 page-fetched 历史及共享 changedContent 规范化；索引摘要变化仍留在原变化台账。下架必须有明确可见删除/停止展示文字；403、404、超时、缺图、无搜索结果均不能单独证明下架。真实重定向保留原 URL 和跳转链；拦截、错误页或最终页不可核实时归无法访问。失败后保留此前成功快照，后续恢复仍可比较。源码无自动结案操作。

`urlCheck.current/history/snapshots/task` 保存在既有线索中。正文按内容哈希复用，原快照采集时间不覆盖；每次结果保留独立检测时间和前状态。跨设备合并以检测时间及稳定ID合并，旧待处理状态不能覆盖新结果。公开投影只含公开页面证据与技术状态，不含人工备注或优先级调整原因。公开业务上传不能伪造自动核查结果。

定时 auto、原扫描/迁移/同步路径分批运行；增加 `url-check` 独立补查操作，不执行检索、Notion 归档或飞书群推送。北京时间09:10至09:45暂停独立检测，自动周期另以09:20截止前一分钟约束预算。正式报告先按原保存凭证封版，后续检测不回写正文。新正式报告保存 frozenUrlCheck；旧报告若展示当前状态，标签显示“当前”及实际检测时间。

## 飞书状态更新

既有初核入表 Webhook 和事件保持不变，`base-fields.mjs` 生成高/中/低和有依据的网址状态，无检测时省略 page_status。自动与人工 pageState 冲突时，自动更新 payload 省略此列，保留人工事实。

新增 `base-status.mjs` 更新专用私有 outbox，使用原 canonical URL 的 source_id 和 platform_lead_url 索引，event_type=lead_status_updated，update_only=true、match_exactly_one=true；fields 仅有 monitor_level、已验证 page_status 和 url_checked_at。不传处理状态、备注、附件或其他人工字段。请求先持久化，code=0 仅算受理；不明确响应不盲目重试，也不对该来源继续发送后续变体。未配置时保留 queued，运行中心展示待接通，不使用创建入口冒充更新。

需要在飞书端配置一个**只更新**的工作流入口并保存为仓库 Secret `FEISHU_BASE_STATUS_WEBHOOK`。接收JSON后：

1. 校验 event_type、update_only、match_exactly_one 和字段白名单。
2. 按现有“平台线索索引”精确查找 platform_lead_url；只有恰好一行才更新，零行或多行停止，禁止新增。
3. 仅映射 fields.monitor_level；仅在 fields.page_status 存在时更新网址状态；记录检查时间。不得映射 processing_status/remarks/图片等。
4. 保留飞书人工确认状态时，需在工作流对人工来源/覆盖保护字段再做判断；工作台无法读取未回传的飞书人工修改，因此未核实前不启用覆盖。

当前可调用工具没有飞书工作流编辑或表格读写能力，已有初核入口也未声明支持此协议，因此本次不替换既有 Secret 或远端工作流。自动建账的新行可使用已取得的状态；旧行自动更新的真实闭环须在该更新入口完成后核验。Mock 受理不等同真实写表。

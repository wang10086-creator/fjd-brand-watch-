# 新增与变化线索整合及变化详情 · 2026-10-20

## 实施边界

在现有 GitHub Pages/Actions、监控台账、优先级及四阶段处理流程上增量实现。保护分支 `backup/delta-changes-before-20261020`，基点 `19f33eaf`；公开快照及原存档索引备份于工作区受限目录。没有清空或迁移原台账，不重新计算历史不可变事件，也不改变 URL 去重规则、定时任务或第三方 API 协议。

依赖：现有 `monitor.observe` 的按日 observation → `reportModel` 原口径 → 日报显示与 `reviewKeys` 范围 → 列表和详情；可选逐次变化明细沿同一 observation 通过 IndexedDB、完整备份、加密云端和公开裁剪同步。

## 日报合并

- 一张“新增与变化线索”卡片：按规范 URL 去重；分别展示新发现与旧变化数量，只计算一套当前优先级。
- 新发现、旧变化及合并优先级仍为独立链接，保留日报日期；优先级链接指向 `scope=delta`。
- 若旧备份同一天同一 URL 同时出现新增/变化，展示集合按新发现优先，防止重复计数。只做显示及相应查询范围归并，不修改旧 observation/reportModel。
- 原待完成核查、成功查询入口、处理进度、七日趋势等仍使用原报表定义。
- 浏览器及 HTML 导出复用相同组件和响应式样式。导出传入当前台账供当前优先级统计，不将人工调整回写成历史时点评级。
- 日期限定的线索页增加紧凑范围下拉，复用原 new/changed/delta/pending/all/repeat 范围。切换时保留搜索、品牌/公司、平台、处理阶段、优先级、跟进和排序条件。

## 变化事实、跟进、处理三个维度

“旧线索新变化”标签仅由现有 `kind=changed` 记录驱动，显示对应日报日期。按日页面只认选定日期；总台账显示最近有依据的历史日期。重复命中、最后发现时间、访问恢复、查询词变化、人工优先级或处理意见不会自行产生变化标签。

`needsRecheck` 仍是原独立跟进字段，界面显示“待重新核对”；它不能代替变化证据。实际变化记录保留，即使已处理也不会伪装成今天新变化。处理阶段、结案、重新打开和人工优先级都不由标签自动推进。

## 前后内容和历史

- 详情证据列新增“页面内容变化”，在基本信息附近；不进入处理/优先级表单，处理卡片仍先于优先级。
- 变化前/后按标题、摘要及可信成对正文字段比较，突出新增（浅绿）和减少（浅红），弱化共同文本；长片段节选，完整实际保存记录可展开。
- 摘要只引用真实差异文字，不推断新增授权、价格或经营行为。索引内容差异明确提示“不能直接证明原网页已修改”；采集口径/查询不一致另有提示。
- 从特定日期进入时默认显示该日期最近一条；可独立点击其他历史记录。切换仅替换对比区域，未提交处理内容和优先级输入不重置。
- 历史缺失前/后内容时明确“历史对比内容不足”，缺失字段不被当成空白或凭空新增；原记录及时间保留。
- 旧版仅有按日 `before/snapshot` 的记录继续直接读取，并明确其归并性质。没有变化的普通线索不出现空白大模块。

## 采集记录兼容扩展

保留原 `snapshot()` 字段和原始文字。`observe()` 继续沿用原可比查询/标题/内容信号的变化判定边界，比较时仅规范化 HTML/Markdown 强调、大小写、空白、部分排版和明确的检索时间元数据；商品内容中的实际促销日期仍属于可比文字。

为今后实际检测到变化的旧线索，在原 observation 上可选追加 `contentChanges`：每项有稳定操作 ID、实际时间、真实 before/snapshot。这样同一天的后续不同查询即使刷新 observation.snapshot，也不会覆盖先前已检测变化的真实配对。若已有旧版归并记录同日又有新变化，先保留其旧对比为明确标注的 legacy 项，再追加新配对。

`mergeMonitors` 按 ID 合并新增明细，保留不同设备的记录，重复合并幂等；公开版本只白名单发布内容字段，处理依据、内部备注和其他未知私有字段不进入公开数据。加密完整备份及证据索引自动保留扩展字段。没有为旧事件强制生成明细或重算原事件校验值。

## 客观限制

现有历史主要保存搜索索引标题及摘要，不能还原未保存的完整原网页或推定真实网页在何时修改。只有两侧均有可信的 page-fetched 正文时才展示为正文采集对比。本次未新增原站访问绕过或第二套网页变化抓取系统，也未向真实 Notion/飞书发送测试消息。外部写入仍由原接口执行；本次对相关序列化、导出及同步路径进行本地/CI 回归，不能将其表述为真实外部写入已重新验收。

补充回归：历史排序按实际时间戳比较，支持 UTC 与带时区偏移记录混排；新变化操作 ID 保留完整 Unicode 输入。原有处理、优先级、配置、手动失败续跑、公开读取、镜像及历史证据的 10 组浏览器回归均通过。

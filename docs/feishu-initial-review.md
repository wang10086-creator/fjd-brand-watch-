# 初核线索直接写入飞书台账

工作台提交“待IP对接人初核 → 疑似侵权·待IP部门复核”后，沿用原云端加密同步通道，向飞书多维表格工作流提交该条线索。普通检索、信息不足、排除、辅助事实保存和IP部门后续转交都不触发。

## 云端设置

在原仓库 Actions 的 Repository secrets 配置 `FEISHU_BASE_REVIEW_WEBHOOK`，值为飞书工作流的现有接收入口。不要填写群机器人地址，不要把实际地址提交到代码、公开说明或日志。

无需新增飞书应用、OAuth 权限或群机器人。飞书侧由已配置的工作流创建/修改记录。公开网页只使用现有云端同步权限；不直接持有飞书写入入口。网页端的复核仍须通过现有数据密码和执行权限同步到云端；仅保存本机的操作不能自动入表。

`cloud/config.json` 中 `feishuNotifications: true` 保留原有日报定时群推送、发送回执与Notion归档。只取消单条初核线索写入台账后的额外群通知；飞书入表工作流没有消息发送节点。

## 飞书端对应流程

1. Webhook 接收下表中的扁平 JSON。
2. “监测台账”按文本字段“平台线索编号”查找 `source_id`，并排除 `ID = OIM-0001`。
3. 同时校验 `event_type`、`from_stage`、`review_opinion`、非空编号和网址。
4. 找到零条时新增；找到一条时更新；其他情况停止。没有消息发送节点。

原第一条记录不参与修改。现有旧记录没有平台编号时，不自动猜测关联或批量回填。新编号使用规范化原网址的 SHA-256，避免不同设备生成不同本机ID后重复新增。

| 字段 | 内容 |
| --- | --- |
| event_type | ip_initial_review_submitted |
| from_stage | 待IP对接人初核 |
| review_opinion | 疑似侵权·待IP部门复核 |
| event_id | 原复核事件ID |
| source_id | lead- 加规范化网址的SHA-256 |
| monitor_category / source_platform | 平台分类与名称 |
| page_title / url | 原页面标题和网址 |
| country_region | 有所在地依据时填写；检索目标市场单独写入说明 |
| operator_name / product_model | 已有商家和明确型号，缺失时留空 |
| first_found_date / last_checked_date | 已记录的日期，按北京时间转为ISO日期 |
| summary | 页面摘要、初核时间和初核依据 |

新增时填写以上映射。更新时只更新页面标题、所在地、经营者、型号和最近检查日期，保留原首次发现日期、人工状态、处理措施和备注。附件不从网址猜测生成。

## 回执和重试

私有请求队列与原台账一起写入加密保险库。保存请求状态后才向飞书发送；保存失败时停止发送。公开状态仅展示数量和最后尝试时间，不含入口、网址或内部复核依据。

飞书返回 `code=0` 只表示请求受理，界面显示“已受理”，不表示下游写表已经完成。超时、无明确回执、服务器错误或发送中断均保留为“待核对”，不自动重发。明确HTTP429可冷却后有限重试；其他明确拒绝保留失败。相同事件不重复发送，同一线索的不同复核轮次分开处理并保留间隔。

核对飞书运行日志和实际记录后再处理不明确的请求。多维表格查找后新增不是数据库唯一约束，不能承诺严格恰好一次。完整生产验证须从工作台提交一条真实获准的初核，核对实际新增记录、再次处理的更新结果，以及原第一条未变。

## 原浏览器补传与操作触发（2026-10-22 r4）

原浏览器的复核成功落盘后立即请求同步。若保存时已有浏览器后台同步，保留请求并在该同步结束时续交；不等待页面的30秒轮询。真实复核提交跳过旧的五分钟提交冷却和“已有云任务”拦截，云端仍串行处理。一次携带所有尚未被云端接收的复核事件，按事件时间排序，不再每次只发五条。无凭据时明确保留本机记录，并不宣称自动入表。

`review` 操作只验证并保存本次事件、建立对应飞书请求并提交工作流，不执行检索、图片补查、历史入表、Notion补归档或日报群发送。并发组保留单个执行者，使用 GitHub Actions 的 `queue: max` 防止后来的定时任务替换已排队的复核任务；仍有平台排队、容量及失败限制，不承诺即时完成。相同事件只接收一次；原复核和请求先持久保存，才能发送 Webhook。

免 GitHub 凭据的加密导出在分支 API 返回401、403、429或网络失败时，直接读取现有公开密文。密文仍须通过原数据密码的 AES-GCM 校验才会合并，读取与导出不提交任何写入。HTTP401、明确权限拒绝、组织SSO、限流、不可见目标、服务故障及网络/超时分别提示；未知403只说明拒绝访问，不能据此断言缺权限。GitHub网页登录不会自动为工作台建立会话凭据。

加密台账新增按复核事件ID保存的写表回执。运行中心的“重试待写及明确失败请求”只重交既有待写、明确失败或资料待核对请求，保留原复核意见；不重试已受理及回执未确认的请求。后两类应先核对飞书工作流日志及表格。配置缺失/格式错误与已受理分开展示；`code=0` 仍仅表示 Webhook 受理。
